# Exora

**Find what's out there.** Exora is a self-hosted B2B prospecting CRM for small teams. It finds companies and the people who run them in lawful public sources, records where every field came from, checks and scores each record, and gives your team one place to plan outreach, work leads and track results.

It runs on a laptop (Windows, macOS, Linux) or a server (Docker, systemd, Coolify), stores everything in a single SQLite file by default, and needs no paid APIs.

## What it does

| Area | What you get |
|---|---|
| **Discovery** | 13 built-in sources. Find companies in OpenStreetMap, GLEIF, UK Companies House, SEC EDGAR Form D filings, Wikidata, the US NPI registry and the French company register, or add them by domain or CSV. Enrich them from their own websites (Scrapy, robots.txt obeyed), job boards (Greenhouse, Lever, Ashby), news mentions and GitHub. Runs are queued, retried and scheduled, and maintenance jobs re-verify records over time. |
| **Provenance** | Every value is an observation with its source, URL, time and confidence, so you can always answer "where did this come from?". |
| **Verification and scoring** | Domain, MX and website checks; business vs. free-mail and role addresses; phone normalisation; optional SMTP probing; a data-quality score and an ideal-customer fit score with reasons. |
| **Companies and people** | Searchable, filterable tables with facets, bulk actions, notes, tasks, CSV and Excel export, and one-click Word profiles. |
| **Team workflow** | Roles (admin, SDR, viewer), task assignment, a 30-day plan with weekly goals, KPIs with kill thresholds, a daily routine, events and calls/pilots tracking, plus a full audit log. |
| **Outreach (optional)** | A bridge to a separate outreach engine for sequences, human approval of drafts and LinkedIn task lists. Exora works fully without it. |

## Quick start

You need **Git**, plus either **Docker** or **Node.js 24**. Python is installed for you by [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/Jahanzaib211/exora.git
cd exora
```

### Option A: Docker (any OS)

```bash
docker compose up -d --build
docker compose exec app prospector create-user --role admin
```

Open **http://127.0.0.1:8090** and sign in. No `.env` is needed: a session secret is generated on first start and stored on the data volume.

### Option B: Windows (no Docker)

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1
powershell -ExecutionPolicy Bypass -File scripts\start.ps1
```

### Option C: Linux or macOS (no Docker)

```bash
./scripts/setup.sh
./scripts/start.sh
```

The setup script installs uv if it is missing, creates `.venv` from `uv.lock`, builds the web app, writes `.env` with a random secret and asks for the first admin account. Then open **http://127.0.0.1:8090**.

### First steps in the app

0. Optional: load five fictional example accounts to explore with: `uv run prospector import` (Docker: `docker compose exec app prospector import`). The same command imports your own CSV in the [example's format](playbook/accounts.example.csv).
1. **Discovery → New run**: pick a source (GLEIF, Wikidata and OpenStreetMap need no key) and a place, e.g. lawyers in Manchester.
2. Watch **Data engine** as runs complete, then open **Companies** to review, enrich and mark records ready.
3. Edit [`playbook/PLAN.md`](playbook/PLAN.md) to make the Plan, KPIs, Routine and Events screens yours. The app re-reads it automatically.
4. Invite teammates under **Team**.

## Configuration

Everything is set with environment variables or a `.env` file in the repository root. [`.env.example`](.env.example) documents every option. The ones most installs change:

| Variable | Default | Purpose |
|---|---|---|
| `PROSPECTOR_SECRET_KEY` | (generated by setup) | Signs sessions. Required before the app listens on a network. |
| `PROSPECTOR_ORG_NAME` | empty | Your organisation, shown under the logo. |
| `PROSPECTOR_OPERATOR_TIMEZONE` | `UTC` | Timezone for "today", plan weeks and all timestamps. |
| `PROSPECTOR_CONTACT_EMAIL` | empty | Added to the crawler's User-Agent so site owners can reach you; SEC EDGAR requires it. |
| `PROSPECTOR_DATABASE_URL` | `sqlite:///data/prospector.db` | Switch to Postgres for several replicas. |
| `PROSPECTOR_COMPANIES_HOUSE_KEY` | empty | Enables the UK Companies House source (free key). |
| `PROSPECTOR_COOKIE_SECURE` | `false` | Set `true` when users reach the app over HTTPS. |

## Running it for a team

- **Server with Docker or Coolify:** see [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md#3-server-with-docker-compose).
- **Linux server without Docker:** `scripts/setup.sh` plus the systemd unit in [`deploy/exora.service`](deploy/exora.service).
- **Always-on laptop:** `pm2 start ecosystem.config.cjs` (Windows, macOS, Linux).

Never expose port 8090 directly to the internet. Put a reverse proxy with HTTPS in front (Coolify, Caddy, nginx or Cloudflare Tunnel).

## Development

```bash
./scripts/setup.sh --dev          # Windows: scripts\setup.ps1 -Dev
uv run prospector serve           # API + built UI on :8090
cd web && npm run dev             # UI with hot reload on :5173 (proxies /api to :8090)
./scripts/check.sh                # lint, format, tests and web build; Windows: scripts\check.ps1
```

## Responsible use

Exora reads public sources only. It obeys robots.txt, rate-limits every host, identifies itself honestly and never scrapes LinkedIn or evades CAPTCHAs. Contacting people is regulated (GDPR, PECR, CAN-SPAM, PDPL and others): you are responsible for having a lawful basis for any outreach you do with the data it finds.
